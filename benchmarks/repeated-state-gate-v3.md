# Repeated-state gate v3

Status: frozen before representative execution  
Scope: many decisions over one unchanged application state  
Reference runtime: Qwen3.5-2B Q4_K_M GGUF + llama.cpp CPU

## Question

Does comparative semantic v2 provide a useful decision-quality/performance trade-off when several
decisions share one persistent state?

This gate does **not** retry the failed general-purpose scorer-gate v2. A PASS can support only a
repeated-state product scope. Scorer-gate v2 remains the authority for short/fresh general-purpose
use and remains FAIL.

## Why this gate exists

Scorer-gate v2 run `35788235063` showed that semantic v2 was not suitable as a general default:
its short/fresh path lost the `evidence_entailment` family guardrail and was slower than generated
JSON.

Repeated-state diagnostic v2 then produced a different signal on the same pinned 2B artifact. Remote
run `35840582210` measured the same six-of-seven unique correct cases for semantic and generated,
with both methods missing the same performance-regression case. Semantic p50 was 14.98 s versus
68.40 s generated (~4.57x), generated zero answer tokens, and reused about 94.9% of logical input
work. The diagnostic was intentionally too small to promote a product scope.

Gate v3 tests whether that signal survives a broader precommitted workload.

## Frozen workload

Fixture SHA-256:

`f9e5f56128f93efb952f1fc3f4f38441150cb0c29906f688977ffa69ea61338a`

The fixture contains 48 unique decisions in eight shared-state groups. Every group contains one cold
decision followed by five decisions over the identical state. No diagnostic-v2 row is copied as a
special-case acceptance target.

Coverage:

| dimension | frozen coverage |
| --- | --- |
| families | support routing, rule application, evidence entailment, comparative nuance; 12 each |
| candidate counts | 2 candidates: 12; 4 candidates: 24; 8 candidates: 12 |
| state tiers | short: 12; medium: 18; long: 18 |
| arithmetic/time | explicit budget, capacity, schedule, team-size, storage and inventory cases |
| perturbation | normal plus fully reversed candidate presentation order |

The state contains reusable policy/reference context. Each question contains its local facts directly,
so the gate does not depend on opaque-ID lookup. State tiers vary the amount of persistent context;
the runtime report records actual logical/physical token behavior.

## Frozen runtime identity

- source: `unsloth/Qwen3.5-2B-GGUF`;
- revision: `1c466474d208da1a7c4b8cb87ebcdac78f160e34`;
- file: `Qwen3.5-2B-Q4_K_M.gguf`;
- SHA-256: `aaf42c8b7c3cab2bf3d69c355048d4a0ee9973d48f16c731c0520ee914699223`;
- size: `1280835840` bytes;
- `llama-cpp-python==0.3.35`, CPU;
- `n_ctx=8192`, `n_batch=512`, `n_ubatch=512`;
- two scoring threads and two batch threads;
- single-sequence state snapshot/restore;
- repeated-state cache: exact compiler-token-prefix LRU, 2 entries / 256 MiB.

One unmeasured warmup is run for each arm. Within each perturbation, which arm runs first alternates
by shared-state group. Gate latency is computed from the normal-order six-decision sequence, so the
first cold decision is included rather than hidden.

## Precommitted criteria

All criteria must pass.

**Runtime identity.** The exact artifact/runtime settings above must match.

**Overall quality.** Semantic may trail generated by at most 2 correct decisions out of 48, and
generated must not have a statistically significant paired win at exact McNemar `p < 0.05`.

**Family guardrails.** Within each 12-case family, semantic may trail generated by at most 1 correct
decision.

**Candidate-count guardrails.** In each 2/4/8-candidate bucket, semantic may trail generated by at
most 1 correct decision.

**Order robustness.** Semantic must have zero choice changes under complete candidate-order reversal.

**Native invariant.** Semantic must generate zero answer tokens in normal and reversed runs.

**Cache reuse.** The normal semantic run must show exactly 8 cold cache misses and 40 follow-up cache
hits, no shared-prefix fallbacks, cache entries/bytes cleared after every group, and physical input
tokens no greater than 50% of logical input tokens.

**Latency trade-off.** Across complete six-decision groups, semantic p50 and p95 must each be no more
than 50% of generated p50/p95 (at least 2x faster). Semantic group p50 must also be lower than
generated in every short/medium/long state tier.

The 2x threshold is a product-value threshold: a specialized cache/scoring path should deliver a
material benefit, not merely a statistically detectable one. It is deliberately weaker than the
~4.5x diagnostic observation and was frozen before representative gate-v3 execution.

## Interpretation

- **PASS:** evidence supports `NARROW_SCOPE` as the next product decision: semantic v2 is a viable
  candidate for repeated-state decisions on the pinned runtime. It does not become a general-purpose
  default and does not erase scorer-gate v2.
- **FAIL on quality:** choose another scorer or do not promote semantic v2 for this scope.
- **FAIL on cache/performance:** the specialization is not justified as currently implemented; the
  failed criterion remains evidence and thresholds are not weakened.
- **Mixed failure by state tier/candidate count:** consider a narrower scope only through a newly
  frozen experiment, never by reinterpreting this gate after the fact.

Product success remains unknown after a PASS; real developer use would still need to establish that
repeated-state decision workloads are valuable enough to support.
